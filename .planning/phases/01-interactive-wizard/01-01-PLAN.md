<objective>
Create the pure decision/transform layer of the interactive wizard as a new
module `lib/wizard.js`, with no terminal I/O. These functions decide WHETHER to
prompt (WIZ-05 flag-merge, WIZ-06 no-TTY guard), WHAT to prompt for, how to MERGE
flags with answers, and how to render a SECRET-MASKED confirmation summary (WIZ-04).

Purpose: Isolating all branching/masking logic into pure, synchronous functions
makes the wizard fully unit-testable without a TTY and gives Plan 02/03 a stable
contract to build the I/O and CLI wiring against.
Output: `lib/wizard.js` (exported pure functions) + `test/wizard.test.js`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → wizard summary | Confirmation summary text is rendered to a terminal/log surface; raw credentials must not cross into it |
| flags/env → options object | Token/password values enter the process via flags or interactive answers and must not be reflected back verbatim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | buildConfirmationSummary | mitigate | Every secret field rendered via maskSecret; unit test asserts raw secret substring absent from summary output |
| T-01-02 | Information Disclosure | maskSecret | mitigate | Reveal at most last 4 chars; masking computed from length, full secret never concatenated into return value |
| T-01-03 | Tampering | mergeFlagsAndAnswers | accept | Pure function on in-memory copies; flag-over-answer precedence prevents answers overriding explicit operator flags (WIZ-05) |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; Node stdlib only |
</threat_model>
