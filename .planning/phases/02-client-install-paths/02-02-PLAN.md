### CANONICAL SPAWN CONTRACT (single surface — use everywhere)
There is exactly ONE injection surface. Do not introduce alternatives.

- Public installer signature: `installClaudeCode(options, io, { spawn })`.
- Default resolution INSIDE installClaudeCode: `const spawn = deps?.spawn ?? spawnSync;` (spawnSync from "node:child_process").
- `claudeAvailable(spawn)` receives the same resolved `spawn`.
- `finishInit` dispatch (lib/cli.js) calls: `installClaudeCode(effectiveOptions, io, { spawn: io.spawn ?? spawnSync })`.
  - i.e. `finishInit` imports `spawnSync` from "node:child_process" and forwards `io.spawn` if a test attached one, else the real spawnSync.
- Tests capture argv by attaching a `spawn` property DIRECTLY on the test's io object literal (NOT via the shared createIo helper, which must stay spawn-free so the JSON-client tests are unaffected). The fake spawn signature is `spawn(cmd, args) => { recorded.push({ cmd, args }); return { status: 0 }; }`.
- `installClaudeCode` returns the integer exit code. For test assertion of the captured argv, the test reads its own `recorded` array (the fake spawn closure), not a return value.

Do NOT write "deps param OR io.spawn" anywhere. The chain is fixed: io.spawn → finishInit forwards as `{ spawn }` → installClaudeCode resolves `deps.spawn ?? spawnSync`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| init process → claude CLI child | The access token / Keycloak password crosses into a spawned child process. Argv is visible in `ps`; shell history exposure occurs only if shell-interpolated. |
| init process → stdout (CLI-absent / print fallback) | The snippet is printed to the terminal; raw secrets would otherwise be echoed and may be logged/scrolled. |
| lib/config.js clientConfigPath | Previously returned a path Claude Code does not read, silently dropping config in the wrong file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Information Disclosure | claude mcp add token via shell history | mitigate | Invoke spawnSync with an argument ARRAY (never a shell string / `shell:true`); the token is a single array element, never parsed by a shell. Test asserts argv array shape. |
| T-02-04 | Information Disclosure | CLI-absent / print fallback printing raw token to stdout | mitigate | Both the CLI-absent fallback and the --print path render env values through the shared maskSecret-based buildSnippet; tests assert raw token absent and masked tail present. |
| T-02-05 | Tampering | removed clientConfigPath claude-code branch | mitigate | clientConfigPath("claude-code") returns undefined and claude-code removed from JSON_MCP_CLIENTS so no settings.json is ever written; test asserts undefined. |
| T-02-06 | Denial of Service | claude CLI missing causing crash | mitigate | claudeAvailable wraps spawn in try/catch; ENOENT treated as unavailable; installClaudeCode returns 0 with guidance, never throws. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; `node:child_process` is stdlib. No external package added. |
</threat_model>
